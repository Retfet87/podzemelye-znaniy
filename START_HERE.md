## 3. Копия и переход со старой версии

1. Уточни у Сани и команды, что этот токен нигде не опрашивается. Локальная проверка не видит другие компьютеры.
2. Если старый бот работает — останови **его** через Ctrl+C в исходном терминале; дождись «Бот остановлен». Не используй `killall python` и не выключай PostgreSQL ради смены кода.
3. Создай свежую копию непосредственно перед переключением:

```sh
./scripts/backup_mac.sh
```

Архив создаётся атомарно, с правами 600 и проверкой каталога pg_restore; рядом сохраняются SHA-256, время и непубличный отпечаток базы. Значения подключения не выводятся. Ротации и удаления старых архивов нет. Сам скрипт проверяет структуру архива, **не выполняет восстановление**. Реальное восстановление текущей копии уже проверено отдельно; для будущих копий повторяй восстановление только в новой отдельной тестовой базе по DEPLOYMENT.md. Никогда не запускай pg_restore в рабочую базу.

4. **Только если ты решил применить обновление рабочей схемы**, выполни вручную:

```sh
"$(cat .runtime/mac-python)" manage.py migrate
```

Это реальное изменение рабочей базы; агент его не выполнял. Существующая команда применит только отсутствующую 007 под блокировкой/транзакцией. При ошибке — не запускай бот и не правь schema_migrations вручную. Проверь копию и причину. На другом Mac вместо локального указателя используй `.venv/bin/python manage.py migrate`.

5. Повтори проверку и запусти полную версию:

```sh
./scripts/preflight.sh
./scripts/start_mac.sh
```

**Одна команда обычного запуска — `./scripts/start_mac.sh`.** Она сама повторяет проверку, требует целую копию этой базы не старше 24 часов, держит локальную блокировку по токену и запускает обычный `app.bootstrap`, без урезанного/demo-режима. Дополнительная блокировка PostgreSQL защищает от второго актуального poller в этой базе. Токен и MAX ID не печатаются.

Внимание: при запуске используются существующие три флага уведомлений из `.env`. Если они включены, очередь отправляет реальные сообщения. Для контролируемой ручной приёмки владелец заранее выключает `SCHEDULE_NOTIFICATIONS_ENABLED`, `HOMEWORK_NOTIFICATIONS_ENABLED`, `EVENT_NOTIFICATIONS_ENABLED` (значения `0`), затем возвращает желаемые настройки после проверки. Скрипт сам эти настройки не меняет.

## 4. Как проверить и остановить

Терминал остаётся занят. Сначала появляется сообщение запуска, затем после успешного ответа MAX — «MAX отвечает. Long Polling запущен». Открой свой личный диалог с существующим ботом в MAX и отправь `/start`. Проверь главное меню, расписание, личное задание с файлом, мероприятие, полезное, календарь, «Назад»/«Домой». Административные кнопки зависят от роли; права владельца автоматически не возвращаются. Полный сценарий — MAX_CHECKLIST.md.

Для остановки нажми **Ctrl+C один раз** и дождись завершения (worker может завершаться до 20 секунд). После остановки эту же команду можно повторить. При выходе освобождаются локальная блокировка и PostgreSQL lease; файл локальной блокировки намеренно остаётся, удалять его не требуется. На время работы Mac должен оставаться включённым и иметь интернет. Это не установленный автозапускаемый сервис.

## Типичные ошибки

- **Нет 007 / схема не совпадает:** свежая копия → отдельная проверка восстановления → осознанная ручная команда миграции выше. Не удаляй базу и не игнорируй проверку.
- **PostgreSQL недоступна:** проверь статус нужного каталога, порт в локальном `.env`, пароль и права. Не отправляй DATABASE_URL в чат. Проверка стартера скрывает ответ сервера и пароль.
- **Обнаружен другой процесс:** вернись к исходному терминалу и останови прежний бот. Проверка консервативна и может увидеть другой Python main.py; уточни процесс, не обходи запрет вслепую.
- **Нет свежего backup:** выполни `./scripts/backup_mac.sh`. Повреждённая копия, другая база и архив старше 24 часов не принимаются.
- **Python/зависимости:** на этом Mac уже настроен игнорируемый `.runtime/mac-python` на существующее окружение 3.12. Оно сохраняется после завершения задания. На новом Mac подготовь окружение командами ниже, без копирования чужого `.env`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

- **Видео:** нужен ffprobe в PATH. На этом Mac используется ранее разрешённая локальная сборка через `.runtime/media-bin`; ничего системного не устанавливалось.
- **pg_dump/pg_restore:** с разрешения владельца локально размещён клиент PostgreSQL 16.15 из официального Postgres.app 2.9.6; SHA-256 образа сверена с GitHub release digest. Папка `.runtime/pg-client`, сервер не заменялся. Новая версия клиента совместима с сервером 16.9. Скрипты добавляют её в PATH только своего процесса.
- **401 MAX:** проверь актуальность локального токена у владельца, не публикуй его. Формат токена проверен, авторизация рабочим токеном здесь не выполнялась.
- **TLS:** не отключай проверку. Сохрани корректный `MAX_CA_FILE`; реальный TLS к platform-api2.max.ru проверен запросом без токена (ожидаемый 401).

Официальный MAX считает Long Polling средством разработки/тестирования и рекомендует Webhook для production: https://dev.max.ru/docs-api/methods/GET/updates . Для хакатона сохранён проверенный Long Polling; миграция на Webhook в это ограниченное задание не входит. Merge main не нужен для запуска финальной ветки и здесь не выполнялся.
