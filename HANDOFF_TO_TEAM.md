# Передача «Подземелья знаний» команде

Проект — прототип хакатона. Продолжайте существующий код в `review/team`, PR №1 в `main`. Основная инструкция запуска — [DEPLOYMENT.md](DEPLOYMENT.md), demo — [DEMO.md](DEMO.md), границы проверок — [VALIDATION.md](VALIDATION.md). Не копируйте рабочий `.env` в демонстрацию или Gemini.

## База, миграции и формы

Обычный локальный бот получает `DATABASE_URL` из приватного `.env`, только loopback. Compose использует сервис `postgres` и отдельные `POSTGRES_*`. Заполненные файлы настроек не коммитить. PostgreSQL хранит и сами вложения; том `pgdata` должен сохраняться. Пул `DB_POOL_MAX_SIZE=0` по умолчанию; включение требует проверки нагрузки, а не слепого копирования прежних чисел из PERFORMANCE.md.

Схему обновляет только `python manage.py migrate`, с общей транзакционной блокировкой миграций. Сейчас файлы 001–007. Рабочая база в этой итерации не обновлялась: перед будущим переключением нужны свежий backup и восстановление отдельно. Старый процесс не заменять до согласия владельца.

`form_drafts` содержит приватные данные формы, включая вложения в JSON/base64, только 30 минут бездействия, до 16 активных форм на базу. Это не бессрочная записная книжка. Истёкшие строки очищаются при следующем личном запросе. Новая форма, продолжение и отмена сохраняются в PostgreSQL. Router связывает публикацию и удаление черновика одной транзакцией; репозитории используют вложенные savepoint. Подтверждение всегда по токену и текущим правам. Нельзя добавить ручной commit внутри репозитория, вызываемого из такого диалога: он разрушит эту гарантию. Файлы черновиков входят в backup и требуют тех же ограничений доступа.

## Роли

Студент видит свою группу и собственные личные задания, записывается на опубликованные мероприятия. Администратор группы управляет общими заданиями своей области, предлагает мероприятия и редактирует разрешённые материалы. Супер-администратор задаётся единственным MAX ID в локальной конфигурации, публикует расписание/мероприятия и выдаёт роли. Реальные ID в документацию не добавлять. Скрытая кнопка не заменяет серверную проверку прав. После восстановления черновика права проверяются заново при сохранении.

## Расписание, календарь, уведомления

XLS-парсер рассчитан на проверенный четырёхстрочный BIFF XLS АКВТ. Числитель определяется явно заданным понедельником. Замена на одну дату и базовое расписание — разные области: нельзя расширять замену на другие даты. `schedule_publisher` сравнивает данные, блокирует сомнительный импорт, создаёт preview и применяет его атомарно после подтверждения администратора.

`python manage.py check-official-schedule` только перечисляет официальные XLS. Выбор файла, периода и предпросмотр описаны в [INTEGRATIONS.md](INTEGRATIONS.md). Проверка никогда сама не публикует изменения. При недоступном сайте старое расписание остаётся в базе.

Кнопка «📆 В календарь» отправляет `.ics` своей группы за выбранную неделю или одного опубликованного мероприятия. Время Europe/Samara; неизвестный тип недели/незагруженная дата блокируют неточный файл. Календарь — скачиваемый снимок, не подписка. Повторный импорт и обновление календаря зависят от приложения телефона.

Очереди расписания, заданий и мероприятий хранятся в PostgreSQL. Есть уникальность, повторные попытки, задержки, статусы и запрет demo-рассылок. Не обещать абсолютную exactly-once доставку: сервер MAX мог принять сообщение до обрыва ответа. Тесты используют подставной клиент. Рассылки в конфигурации по умолчанию выключены.

## Demo и проверки

Следуйте DEMO.md: отдельный Compose-проект, отдельная база/роль, маркер, разрешённые аккаунты, отдельный тестовый токен и выключатель. Seed нельзя запускать в рабочей базе; обычный бот отказывается от demo-маркера. Все 32 карточки сохранены, данные явно помечены «ДЕМО». Горячее выключение закрывает доступ без удаления данных. Для показа замены используйте только demo-БД. При отсутствии второго токена показывайте автоматический сценарий с OfflineMAX; рабочий токен не дублировать.

Быстрая проверка без настроек и сети MAX:

```sh
python -m scripts.test_offline
```

Полный набор: `VALIDATION_DATABASE_URL=... VALIDATION_DEMO_DATABASE_URL=... AKVT_TEST_XLS=/absolute/public.xls python -m scripts.test_isolated`. Это только подготовленные отдельные базы с маркером `public.validation_environment`; runner не создаёт маркер за вас. Не указывайте рабочую базу. Для простого сквозного сценария на отдельной `*_test`: `TEST_DATABASE_URL=... python -m scripts.smoke_test`. Docker целиком: `sh scripts/check_docker.sh`, без токена, с отдельными томами, backup/restore и пересозданием контейнеров. Пропущенные тесты не считаются пройденными.

## Задачи Сани: развитие mini-app с Gemini

Продолжать `web/index.html`, `web/app.js`, `web/style.css`; точные имена сверить в папке. Уже есть мобильная страница с расписанием, заданиями и мероприятиями, пустые состояния и темы. Не создавать параллельный проект и второй способ авторизации. Сервер и формат ответов — в `app/web.py`; GET `/api/schedule`, `/api/homework`, `/api/events` используют существующие репозитории.

На каждый запрос клиент передаёт `X-Max-Init-Data` из MAX Bridge. Сервер сам проверяет HMAC и срок, получает пользователя из подписанных данных. Нельзя доверять `initDataUnsafe`, query `user_id`, localStorage, роли из JS; нельзя помещать токен бота в браузер. API сейчас read-only, не выдаёт содержимое файлов и скрывает чужие личные задания/неопубликованные события. Сохранить запрет записи, проверки demo allowlist/hot switch и запрет demo-БД в real-режиме.

Сане осталось согласовать экраны: подробная карточка задания, детали мероприятия и история с итогами, «Полезное», навигация назад, реальные загрузка/ошибка/истёкшая сессия на телефоне. Новые данные и операции API требуют отдельного решения и серверных тестов прав. Отдельная задача — разрешённый HTTPS-хостинг, reverse proxy с лимитами, подключение URL на платформе MAX и проверка настоящей подписи запуска. Локальный WSGI не публиковать напрямую. Подробности и первичные ссылки — WEB.md.

После изменений обязательны `test_web.py`, `test_validation_boundaries.py`, `test_demo_security.py`, общий изолированный набор и проверка светлой/тёмной темы на iOS/Android. Ни локальный HTTP-тест, ни скриншот в браузере не подтверждают запуск внутри MAX. В этой доработке mini-app не расширялся.

## Что ещё требует проверки и что беречь

Телефонный прогон новых календарных кнопок/импорта `.ics`, восстановление формы после реального рестарта MAX-бота и визуальный web-прогон остаются ручной приёмкой. Чек-лист — DEMO.md. На Mac отсутствует Docker; его выполнение подтверждается только результатом Actions в VALIDATION.md. Автоматический backup/ротация в рабочей среде не включались. Проверка каталога дампа не равна восстановлению.

Нельзя без предварительной проверки менять TLS, подпись MAX, границы ролей, SQL-функцию доступа homework, advisory locks/reset пула, demo-маркеры, политики отправки файлов, подтверждение импорта, записи `schema_migrations` и имена существующих томов. Нельзя запускать два poller с одним токеном: новая DB-сессия удерживает lease для одного токена в данной базе, но другую базу/другой сервер она не контролирует. Нужна также договорённость команды об одном развёртывании.

## Git и PR

До работы — `git status`, `git fetch origin`, сверка ветки/HEAD. Изменения делать небольшими коммитами в своей ветке; описывать проверки. Не объединять независимые истории и не использовать force push. PR №1 объединяет review/team в main; merge и переключение рабочего процесса выполняет владелец после приёмки. Не подмешивать незнакомые ветки целиком без просмотра diff. Не коммитить `.env`, дампы, логи с данными, initData или реальные MAX ID. Перед передачей Gemini давать этот документ и нужные файлы кода без приватных настроек.
