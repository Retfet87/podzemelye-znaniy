# Проверка MAX перед выпуском

Этот список выполняется после отдельного разрешения на запуск проверяемой версии. Сейчас PR не объединяется, рабочий экземпляр не переключается. Используй выделенный тестовый аккаунт и группу. Если бот только один, сначала согласуй краткое переключение; два Long Polling с одним токеном не запускай.

1. Демонстрационные записи загружай только в отдельную тестовую базу по UX_DEMO.md. Не заполняй ими рабочую базу. Сделай свежую резервную копию рабочей базы и проверь восстановление в отдельную базу. Сохрани прежний коммит и настройки для возврата. На время проверки отключи три флага рассылки. Не публикуй общие тестовые данные для настоящих студентов.
2. Со студенческого аккаунта открой `/start`, проверь первую иллюстрацию, выбери «🏫 АКВТ», направление и тестовую группу. Повторный `/start` сохраняет группу и не повторяет иллюстрацию. На каждом вложенном экране проверь «🏠 Домой» и отдельный «⬅️ Назад». Из формы выход домой должен спросить подтверждение, а отказ — сохранить введённые поля. Старое подтверждение не должно удалить новый черновик. Проверь главные кнопки и «Назад».
3. Открой «Сегодня», «Завтра», «Неделя». Сверь реальные предметы, время, преподавателя, кабинет и числитель/знаменатель, включая разделённую пару. Серый цвет сам по себе не должен менять корпус.
4. Создай личное задание с TXT, просмотри предпросмотр, сохрани, открой файл, отредактируй и удали задание. Второй студент не должен видеть его. Проверь отмену формы.
5. Под администратором подготовь явно помеченное мероприятие, проверь предпросмотр и отмену. Запись, повторное нажатие «Пойду», счётчик и «Не пойду» проверяй на заранее согласованном тестовом мероприятии. Создание/публикация недоступны студенту. Проверь PNG/JPEG и MP4, несколько медиа, теги и фильтры. В «📸 Как это было» отличи обычную запись истории от явно опубликованного отчёта; фото и видео проверь на iPhone и Android, если доступны.
6. Открой категории «Полезного», реальную проверенную ссылку и тестовый файл. Проверь редактирование и отмену с нужной ролью, запрет изменения студентом. Удали созданные тестовые материалы.
7. Предпросмотр обновления расписания для тестовой группы: до подтверждения ничего не меняется и сообщения не отправляются; отмена сохраняет расписание. Подтверждение реального импорта — только по отдельному согласованному решению. Групповую адресацию и ошибки доставки сначала подтверждают автоматические тесты.
8. Для отдельной проверки доставки согласуй одного получателя и одну тестовую группу. Оставляй массовую рассылку выключенной до этого согласования. После проверки верни исходные настройки рассылки и убедись, что в очереди нет тестовых сообщений реальным студентам.

Запиши результат каждой проверки, коммит, аккаунт/роль без MAX ID и время. Сбой внешнего API или кнопок блокирует выпуск до исправления. Успешный workflow сам по себе не разрешает объединение PR или рабочее развёртывание.

## Итоговая приёмка 8 ноября — что выполнить владельцу

Автоматические проверки и браузерный просмотр нового сайта не являются реальным прогоном MAX. В этой разработке MAX-запросы с рабочим токеном не выполнялись. Не останавливать/переключать рабочий экземпляр без согласия, не запускать второй poller, не включать тестовые массовые рассылки.

- [ ] Зафиксировать тестируемый коммит и окружение. Если нужна миграция старой базы — сначала новая проверяемая копия и восстановление отдельно. Demo seed только в отдельной demo-базе; на публичном сайте JSON уже готов, seed не нужен.
- [ ] Новый студент: АКВТ → направление → группа; повторный `/start` и «Домой» сохраняют группу. Проверить сводку и простые вопросы «что завтра», «когда физика», «кто куратор», «что задали».
- [ ] Сегодня/завтра/неделя, числитель/знаменатель, замена одной даты. Скачать `.ics` и проверить время/предметы на телефоне. Неизвестная чётность должна давать честный отказ экспорта.
- [ ] Личное/общее задание с файлом, предпросмотр/отмена/правка, продолжение формы после разрешённого рестарта тестового процесса в пределах 30 минут. Второй студент не видит личное задание первого.
- [ ] Роли: студенту недоступно редактирование общих материалов/публикация; администратор группы действует только в своей области; супер-администратор подтверждает импорт/публикацию. Старые кнопки не выполняют повторное действие.
- [ ] Мероприятия: теги, PNG/JPEG/MP4, «Пойду» дважды без дубля, отмена участия, итоги прошедшего события. Полезное: категории, проверенная ссылка и файл.
- [ ] Уведомления заданий: из главного меню возврат домой, из заданий — назад к заданиям; переключение категории сохраняет этот контекст. Доставку проверять только на согласованном одном получателе, массовые флаги не включать ради показа.
- [ ] Сайт открывается обычной HTTPS-ссылкой без авторизации/MAX ID, все четыре раздела непустые, 32 полезные карточки, фото/видео, TXT/.ics, светлая/тёмная тема, узкий экран. Это отдельный сайт, не встроенное mini-app. Пробная запись только в памяти вкладки.
- [ ] До публикации URL кнопки сайта нет; после задания PUBLIC_DEMO_SITE_URL — только реальный HTTPS, не localhost. Сайт не читает рабочую БД; защищённый API без initData по-прежнему 401.
- [ ] Записать результат каждого пункта: устройство, версия MAX, время, коммит, найденные проблемы — без MAX ID и токенов. Сделать запасное видео показа.
