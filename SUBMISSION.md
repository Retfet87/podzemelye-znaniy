## Что реализовано

- Общий date_picker для заданий и мероприятий: сегодня/завтра/послезавтра/+7 дней, произвольный день календарём, переходы месяцев/лет, быстрые часы, свой час, необязательный ручной ввод. «Без срока» только для заданий. Просроченное время отклоняется. Часовой пояс соответствует существующему правилу UTC+4 Астрахани.
- Каждый переход использует существующий одноразовый токен формы. Состояние календаря — дополнительные поля JSON-черновика с defaults, старые payload и позиционные аргументы Draft сохранены. Публикация и права остаются в прежней транзакции. Новых миграций нет.
- Следующая неделя — семь дней следующей недели календаря, с тем же SQL выбора версии/официальным anchor. Разовая замена имеет приоритет только на своей дате. За valid_to нет прогноза, бот сообщает, что расписание пока не опубликовано. Неизвестная чётность не угадывается, каникулы без источника не выдумываются.
- Контекстные вопросы: сегодня, пары завтра, следующая неделя, первая пара, предмет, что задали, задания со сроком завтра, ближайшие события. Только разрешённые записи актёра; due_list использует тот же SQL ACL. Неизвестный запрос предлагает меню, LLM нет.
- Пустые задания/мероприятия/материалы сообщают об отсутствии данных и сохраняют навигацию.
- DEMO: отдельная защищённая БД, условные четыре недели через границу года, явный anchor, однодневная замена, разный срок заданий/без срока/TXT, будущие и прошлые события/медиа/RSVP, 32 материала из пяти категорий. --synthetic-schedule не заменяет чужие импорты. --clean + повторный seed повторяют сценарий без ручной правки записей. Рабочая база не наполнялась.
- Нет нового пула/параллельного dispatch/supervisor. Сохранены backoff, очередь, dedupe, транзакции, блокировка пользователя и polling lease. Убрано дублирование логики выбора дат через один модуль; большой косметической чистки нет.
