# UX и демонстрация

## Что изменилось

Первый вход: `/start` → иллюстрация и «🏫 АКВТ» → направление → группа → главное меню. Картинка оригинальная, сгенерирована для проекта; статический файл `assets/welcome.png`. Она отправляется один раз при первоначальном приветствии, а не при переходах домой. Если загрузка изображения недоступна, регистрация продолжает работать текстом. Ранее зарегистрированные студенты привязываются к АКВТ по группе и не проходят регистрацию заново.

Миграция `006_ux.sql` добавляет учреждения, связь групп/пользователей с учреждением, отметку приветствия, теги, поля отчётов, медиа и метки демо-записей. Она не запускается автоматически в рабочей базе в рамках разработки. Перед будущим применением к рабочей базе нужны резервная копия и проверка восстановления.

## Навигация по экранам

| Экран | Назад | Домой |
|---|---|---|
| Учреждение / направление / группы | От группы к направлению | На выборе учреждения отсутствует, на следующих шагах возвращает к учреждению |
| Главное меню | Не требуется | Не показывается |
| Расписание: сегодня, завтра, неделя | Меню расписания | Главное меню |
| Задания: список, карточка, файл | Список / меню заданий | Главное меню |
| Настройки уведомлений | Из заданий — меню заданий; из главного — только Домой | Главное меню |
| Мероприятия, фильтры, история | Категория / список | Главное меню |
| Карточка, медиа, итоги | Мероприятие / список | Главное меню |
| Полезное, категории, преподаватели, файлы | Категории / карточка | Главное меню |
| Пошаговые формы заданий, мероприятий, материалов, отчёта | Предыдущее поле | Подтверждение выхода без сохранения |
| Подтверждение удаления, публикации, отмены, назначения роли | Явная отмена | Подтверждение выхода без выполнения действия |
| Ошибка или устаревшая кнопка | Возврат через доступную клавиатуру | Безопасный переход домой |

«Домой» закрывает черновик только после подтверждения владельцем. Старое подтверждение не удаляет новый черновик. Открытие другой формы при незавершённой форме также требует завершить/отменить текущую. Формы сохраняются в PostgreSQL и восстанавливаются после перезапуска в течение 30 минут бездействия. Публикация и удаление формы атомарны; отменённые/истёкшие формы не возвращаются. Это реализовано миграцией 007, подробности — HANDOFF_TO_TEAM.md.

## Фото, видео и отчёты

Супер-администратор создаёт событие; администратор группы предлагает его. В форме можно выбрать несколько тегов и до трёх медиа. Сохранение черновика и публикация — разные подтверждённые действия. Первая фотография/видео показывается в карточке, остальные доступны кнопкой медиа. Для совместимости с MAX несколько видео отправляются отдельными сообщениями с навигацией.

Поддерживаются PNG/JPEG до 5 МБ и 7680 × 7680 и MP4 до 20 МБ. Это более строгие пределы проекта, чем API. Изображения проверяются Pillow, видео — ffprobe с ограничением времени и протокола; пользовательское MIME не считается доказательством формата. В Docker ffmpeg/ffprobe установлены. Для локальной работы с видео их нужно установить отдельно. Файлы хранятся в PostgreSQL, временные CDN-ссылки не сохраняются как содержимое.

Официальный контракт: https://dev.max.ru/docs-api/use-cases/sending-messages/media/ и https://dev.max.ru/docs-api/methods/POST/uploads. Для image используется результат загрузки photos/token, для video — token из POST /uploads. TLS и существующая проверка CDN сохранены. Перед показом на настоящем MAX нужно проверить отображение этих вложений в клиенте.

«📅 Предстоящие» и «📸 Как это было» различаются по времени. Прошедшее опубликованное событие попадает в историю автоматически, но итоги не появляются автоматически. Только супер-администратор после окончания события публикует отчёт через предпросмотр; отчёт содержит итоги, необязательную ссылку и медиа. Публикация отчёта не создаёт рассылку. Для длинных итогов есть отдельная карточка.

## Демо-наполнение

Только отдельная база с именем `*_test` или `*_demo`, без рабочего токена и отправителя. Применить миграции можно через существующий manage.py с отдельным конфигом либо при подготовке изолированной Compose-базы. Не направляй команды на рабочую базу.

Подготовка изолированного демо-окружения, выключатель и безопасные seed-команды описаны в [DEMO.md](DEMO.md). Прежние команды с `TEST_DATABASE_URL` больше не являются источником для demo seed. Сохранены 32 явно помеченные карточки из kruto; рабочие контакты не подменяются демонстрационными.

## Показ за 5 минут

1. Новичок: приветствие с иллюстрацией → АКВТ → направление → группа. Затем «Домой», повторный `/start` без повторной регистрации.
2. Неделя: сверить настоящий XLS, показать числитель/знаменатель и разделённую пару. Вернуться «Назад», затем «Домой».
3. Личное задание: предмет → текст → без срока → TXT → предпросмотр → сохранить. Открыть файл. Начать редактирование и выйти домой через подтверждение.
4. События: фильтр «Хакатоны» → карточка и медиа → «Пойду» дважды (счётчик не дублируется) → «Не пойду». История → демо-отчёт и фото.
5. Полезное: пять категорий, TXT и проверенная ссылка. Под студентом показать отсутствие административных действий. Под администратором показать форму до предпросмотра и отменить.

## Границы проверки

Автоматические тесты используют отдельную PostgreSQL и подставной MAX API. Они не доказывают визуальное отображение на iPhone/Android и реальную обработку загруженного видео сервером MAX. Рабочий бот не останавливался и не переключался. Для настоящей проверки нужен отдельный разрешённый тестовый бот либо согласованное переключение единственного экземпляра на изолированную базу; параллельный Long Polling с рабочим токеном запрещён. До отдельного согласования используйте MAX_CHECKLIST.md и не заявляйте, что ручная проверка уже выполнена.

## Навигационная консолидация kruto

Из дерева `1cd1d23` перенесены только навигационные изменения и тесты, без объединения независимых Git-историй и без опасного seed. На корневом экране расписания нет возврата на самого себя; в результатах возврат ведёт к выбору периода. При наличии «Домой» удаляется дублирующий возврат в главное меню. На выборе учреждения нет самоперехода «Домой». Ручная проверка в MAX этим не подтверждается.


## Финальная репетиция двух продуктов: 5–7 минут

Публичный сайт не зависит от MAX mini-app: открывается обычной ссылкой и использует только вымышленные данные. Предварительно собрать `dist`, для внешнего показа согласовать HTTPS. Бота проверять только в согласованном окружении, не запускать второй poller с рабочим токеном.

| Время | Показ |
|---|---|
| 0:00–1:00 | Бот: `/start` → АКВТ/направление/группа → сводка → сегодня/завтра/неделя. В подготовленной demo-базе показать замену на одну дату и неизменность соседней. |
| 1:00–2:00 | Личное задание, предмет, файл, пропуск срока, предпросмотр, подтверждение; открыть сохранённый файл. |
| 2:00–3:20 | Событие, запись и отмена, теги, прошедший отчёт, полезные материалы и календарь. |
| 3:20–5:30 | Обычная ссылка сайта без входа: расписание/замена, задания/файл, события/пробная запись, итоги/видео, полезное/категории, тёмная тема. |
| 5:30–6:30 | Различие постоянных данных бота и публичных demo-примеров. Показать результаты тестов/restore и назвать оставшиеся внешние проверки. |

Не выдавать эмуляцию мобильного размера браузера за настоящий iOS/Android MAX. На случай недоступности интернета подготовить запись уже проведённой телефонной репетиции владельцем и локальную сборку сайта. Пробная запись на сайте не рассылает уведомления и не меняет PostgreSQL. Авторизация защищённого API сохранена.

## Единый показ выпуска 8 ноября: 6 минут

Заранее открой опубликованный HTTPS-сайт и проверенный владельцем экземпляр MAX. Сам сайт не зависит от запущенного на ноутбуке процесса. Не переключай рабочий бот ради защиты без отдельного согласия; если нужной версии нет, используй резервный показ.

1. 0:00–0:45 — MAX: зарегистрированный студент, повторный /start, группа, главное меню. Группа после регистрации закреплена; самостоятельного перевода между группами в текущем контракте нет.
2. 0:45–1:30 — сегодня/неделя, чётность и разделённая пара; показать подготовленный результат изменения конкретной даты, не делать массовую тестовую рассылку.
3. 1:30–2:30 — личное задание с файлом, предпросмотр, отмена выхода, сохранение. Объяснить разграничение личного и общего задания.
4. 2:30–3:15 — мероприятие, запись/отмена, полезный материал, .ics. Только согласованные тестовый аккаунт и данные.
5. 3:15–5:15 — публичный сайт: расписание, задания с TXT, событие с фото/видео и итогами, пробная запись/отмена, 32 справочные карточки по категориям; светлая/тёмная тема и телефонная ширина. Пробная запись не отправляет сообщения и не сохраняется после перезагрузки.
6. 5:15–6:00 — результаты автоматических проверок, права, изоляция, восстановление. Честно назвать границу: открытый сайт показывает вымышленные данные, реальная база доступна только боту/защищённому API.

### Резерв без интернета или MAX

До защиты собрать `python -m scripts.build_demo_site`, сохранить весь `dist/` и этот репозиторий локально. Временно запустить `python -m http.server 8088 --bind 127.0.0.1 --directory dist` и заранее открыть/проверить http://127.0.0.1:8088. Прямое открытие index.html через file:// не подходит из-за fetch. Локально доступны все JSON, фото, MP4, TXT и календарь; внешняя ссылка может не работать без сети. Это осознанно запускаемый резерв, основной публичный сайт от него не зависит.

Если MAX недоступен — показать заранее сохранённые владельцем экраны реальной приёмки и объяснить сценарий, затем выполнить `node scripts/test_frontend.mjs` и изолированный smoke на подготовленной тестовой базе. Не выдавать снимки или подставной API за живой MAX. Не копировать рабочий токен, БД или личные данные в презентацию.

Новый дизайн сайта: единая спокойная палитра, текстовая навигация без декоративных эмодзи, адаптивные карточки и две темы. Полноразмерные медиа остаются внутри карточек; случайные счётчики участников и рекламный hero удалены.
