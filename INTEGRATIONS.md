# Календарь и ручная проверка расписания

## `.ics`

MAX: «Расписание → 📆 В календарь», стрелками выбрать неделю, скачать файл. Экспортирует только группу текущего пользователя. У опубликованного мероприятия кнопка на карточке. Вложения отправляются существующим MAX upload API. Формат — [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545): CRLF, перенос UTF-8 строк по 75 октетов, экранирование текста, постоянный UID, Europe/Samara. Списки участников и личные задания не экспортируются. Длительность мероприятия не выдумывается, если время окончания неизвестно.

Нет занятий — понятный ответ без пустого файла. Есть незагруженная дата или неизвестный числитель — экспорт отменён, сначала подтвердить исходное расписание. Повторная загрузка — снимок, а не автоматическая синхронизация. Поведение повторного импорта проверить в целевом приложении телефона. Подключение к рабочему MAX в этой итерации не выполнялось.

## Официальный XLS

Источник: [страница АКВТ](https://www.akvt.ru/teachers/raspisanie-zanyatij/). На ней несколько наборов и семестров: программа намеренно не угадывает самый новый подходящий файл.

```sh
python manage.py check-official-schedule
```

Команда без параметров только читает публичную страницу, не открывает базу и не читает `.env`. Затем оператор выбирает точную выведенную HTTPS-ссылку и согласованный период. Пример (даты, ссылка и тип недели должны быть сверены оператором):

```sh
python manage.py check-official-schedule --file-url 'СКОПИРОВАННАЯ_ОФИЦИАЛЬНАЯ_HTTPS_ССЫЛКА' \
  --scope base --from YYYY-MM-DD --to YYYY-MM-DD --numerator-monday YYYY-MM-DD
```

Без `--stage` это сравнение без записи preview и без уведомлений. Для черновика повторить со сверенными `--expect-groups ЧИСЛО --expect-lessons ЧИСЛО --stage`. При отменах нужно явно подтвердить их точное количество через `--expect-cancellations ЧИСЛО`. В реальном проверенном примере были 37 групп и 672 строки, но нельзя автоматически считать эти числа правильными для каждого будущего семестра. Команда выводит SHA256, сравнение и приватную команду `/schedule_confirm TOKEN` для настроенного супер-администратора; отказ — `/schedule_cancel TOKEN`. Токен подтверждения не публиковать в общих чатах. Срок preview — 30 минут; повторный одинаковый pending preview при прежней версии базы переиспользуется. После чужой публикации старый preview требует повторной проверки.

Замена одной даты: `--scope date --from YYYY-MM-DD --group ГРУППА`; она не меняет остальные даты. Базовое обновление всегда с явной конечной датой, никаких автоматических переносов недельных замен. Обычный `import-schedule /local/file.xls` сохранён.

Разрешены только akvt.ru/www.akvt.ru, HTTPS с проверкой цепочки/имени. DNS-адреса должны быть публичными; соединение закрепляется за проверенным IP, редиректы перепроверяются. Ограничены редиректы, размер страницы/XLS, сетевой тайм-аут, сигнатура и структура файла. Недоступность сайта/неподходящая структура завершают проверку без изменения сохранённого расписания. Демонстрация сетевых ошибок в тестах использует заглушки. Сервис по расписанию не добавлялся; эту ручную команду можно позднее вызывать планировщиком только для подготовки preview, с отдельным решением об авторизации и журналировании.
