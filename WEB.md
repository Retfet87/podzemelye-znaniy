# Небольшое web mini-app

Код готов к review; в MAX не подключён и не развёрнут. Наличие кода не означает выполнение критерия 10.4.1: для этого нужен фактический запуск в MAX и ручная проверка интерфейса. Оригинал правил организатора всё ещё требует сверки.

## Возможности

Одна мобильная страница, три вкладки: расписание недели, последние доступные общие/личные задания, ближайшие опубликованные мероприятия. Используются существующие репозитории и их права. Полные списки и редактирование остаются в боте. Размеры рассчитаны на узкий экран, есть светлая/тёмная темы, загрузка/ошибка/пустые состояния. Весь пользовательский текст выводится через textContent.

Статика доступна без входа; API требует MAX initData в заголовке `X-Max-Init-Data` на КАЖДЫЙ запрос. Вход по `user_id` из URL, initDataUnsafe или локальному тестовому переключателю отсутствует. JSON/статика no-store; cookies и localStorage для авторизации не используются. Query parameters и запись через API запрещены; CORS не открыт. Авторизация ограничена 5 минутами с допуском будущего времени 30 секунд — это политика проекта, не утверждение об обязательном лимите MAX. После истечения нужно повторно открыть mini-app из MAX. Без группы предлагается регистрация в чате.

Подпись проверяется на сервере по официальным источникам, просмотренным 7 ноября 2026:

- [MAX Bridge](https://dev.max.ru/docs/webapps/bridge): официальный скрипт https://st.max.ru/js/max-web-app.js и window.WebApp.initData.
- [Валидация](https://dev.max.ru/docs/webapps/validation): HMAC с ключом WebAppData, сортировка параметров, исключение hash и постоянное по времени сравнение подписи. Дубли параметров и некорректное кодирование отклоняются.
- [Подключение](https://dev.max.ru/docs/webapps/introduction): HTTPS-адрес должен быть привязан к боту на платформе партнёров; после этого платформа показывает кнопку открытия. Эта настройка здесь не менялась. Встроенную кнопку в основном меню бота не добавляли, поскольку URL/доступ к подключению пока не подтверждены.

## Отдельное включение

`mini_app.py` по умолчанию выключен. Не запускает Long Polling, миграции, seed или уведомления. Оператор явно задаёт:

- `WEB_MODE=real`, `WEB_DATABASE_URL` (только явный loopback), `WEB_MAX_BOT_TOKEN` — только для серверной проверки подписи. Файл `.env` не читается. Demo-маркер запрещён в real-режиме.
- либо `WEB_MODE=demo`, `DEMO_DATABASE_URL`, `WEB_MAX_BOT_TOKEN` **от отдельного тестового бота**, а также demo allowlist, `DEMO_ENABLED` и `/run/demo/enabled` из DEMO.md. Hot switch проверяется до чтения и перед ответом. Все ответы маркируются `demo: true`, интерфейс показывает «ДЕМО».

Входной server — локальный WSGI на 127.0.0.1:8080. Это сервер разработки, не публичный production deployment. Для реального показа нужны WSGI-serving/reverse proxy по HTTPS с ограничением запросов/заголовков/таймаутов, секреты только на сервере и настройка платформы MAX. Публикация, подключение и работающий бот требуют отдельного согласованного этапа; в этой итерации они не выполнены. Публичное открытие порта или запуск через рабочий `.env` не предлагаются.

## Проверки и ограничения

Есть синтетические тесты HMAC, Unicode/кодирования, дубликатов hash/user, неверного токена/подписи, старой/будущей даты, чужого query ID пользователя, запрета записи, hot switch и безопасных ошибок. Это проверки собственного кода, не реального сервиса MAX. Добавлен PostgreSQL-тест разделения личных/групповых заданий и сокрытия неопубликованных мероприятий; он пока пропущен из-за отсутствия PostgreSQL.

Локальный просмотрщик не смог открыть временный статический preview (таймаут); сервер preview остановлен. Визуальная проверка, iOS/Android, реальная подпись запуска, HTTPS/настройка платформы, Docker build и чтение реальной PostgreSQL не выполнены. Текущий UI/транспорт нельзя объявлять подтверждёнными в MAX до этих проверок. Числа нагрузки и баллы жюри не заявляются.
